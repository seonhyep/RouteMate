# RouteMate · 루트메이트 MVP

Kotlin + Jetpack Compose + Room으로 만든 일반 Android 스마트폰용 프로젝트입니다.
로그인과 API 키 없이 실행됩니다. 외부 AI·지도·차량 SDK를 연동한 앱이 아니라, **규칙 기반 문장 분석과 명시적으로 표시한 데모 이동 데이터**로 핵심 흐름을 시험하는 첫 버전입니다.

## 검증 상태

- Kotlin 2.0.21 / Java 17로 순수 Kotlin 핵심 코드와 JUnit 테스트를 실제 컴파일했습니다.
- **단위 테스트 52개 통과**: 문장 분석 30, 추천 14, 차량 상태 전환 8.
- 별도의 정적 검토에서 발견한 다음 이동 추천, 미루기, 실제 장소 보존, 일괄 저장 원자성, 탭 이동·화면 회전 중 입력 보존 문제를 수정했습니다.
- **전체 Android 앱의 Gradle 빌드, 에뮬레이터·실기기 실행, Room 계측 테스트는 이 제작 환경에 Android SDK가 없어 실행하지 못했습니다. APK는 포함하지 않습니다.** 아래 절차로 Android Studio에서 확인해 주세요.
- 전체 검증 범위와 실제 테스트 출력: [docs/VERIFICATION.md](docs/VERIFICATION.md)

## 1. Android Studio에서 실행

1. ZIP을 압축 해제합니다. 경로가 짧은 폴더(예: Windows의 C:/Projects/RouteMate)를 권장합니다.
2. Android Studio **Ladybug 2024.2.1 이상**에서 **Open**을 누르고, settings.gradle.kts가 들어 있는 RouteMate 폴더를 선택합니다. 단일 app 폴더가 아닙니다.
3. **Settings → Build, Execution, Deployment → Build Tools → Gradle**의 Gradle JDK를 **JDK 17**로 설정합니다. 설치된 Studio 런타임이 다른 버전이면 JDK 17을 별도로 선택/다운로드하세요.
4. **SDK Manager**에서 Android SDK Platform **35**와 Android SDK Build-Tools, Platform-Tools를 설치합니다. SDK 위치는 Android Studio가 local.properties에 자동 기록합니다. 이 파일은 개인 환경 경로이므로 배포본에 넣지 않았습니다.
5. **Sync Project with Gradle Files**를 실행합니다. 최초 실행에는 Gradle·Google Maven·Maven Central 의존성 다운로드를 위한 인터넷 연결이 필요합니다. 앱 자체의 핵심 기능은 이후 오프라인으로 작동합니다.
6. Android **8.0(API 26) 이상** 에뮬레이터 또는 USB 디버깅을 허용한 스마트폰을 연결합니다. 권장 테스트 기기는 API 35, 세로 360dp 이상입니다.
7. 실행 구성을 **app**으로 선택하고 Run을 누릅니다. 첫 실행 때 할 일 3개가 자동 생성됩니다.

### 터미널 명령

Windows PowerShell:

~~~powershell
.\gradlew.bat --version
.\gradlew.bat testDebugUnitTest
.\gradlew.bat assembleDebug
.\gradlew.bat connectedDebugAndroidTest
.\gradlew.bat installDebug
~~~

macOS / Linux:

~~~sh
chmod +x gradlew
./gradlew testDebugUnitTest assembleDebug
./gradlew connectedDebugAndroidTest
./gradlew installDebug
~~~

- 계측 테스트·설치 명령에는 연결된 기기/에뮬레이터가 필요합니다.
- APK 생성 위치: app/build/outputs/apk/debug/app-debug.apk
- 단위 테스트 보고서: app/build/reports/tests/testDebugUnitTest/index.html
- Room 계측 테스트 보고서: app/build/reports/androidTests/connected/debug/index.html
- 음성 인식은 에뮬레이터 이미지에 따라 제공되지 않을 수 있습니다. 텍스트 입력은 항상 가능합니다.

## 2. 빠른 데모 시나리오

**실제 운전 중이 아닌 안전하게 정차한 상태에서 테스트하세요.**

1. **홈**에서 우유 구매, 세탁소에서 옷 찾기, 택배 보내기 등 샘플 할 일 3개를 확인합니다. 샘플 할 일, 경로, 차량 상태에는 각각 **데모** 표시가 있습니다. 마감은 최초 실행일 기준 오늘·어제·이틀 뒤입니다.
2. **할 일 등록**에서 다음 문장을 입력하고 **문장 분석하기**를 누릅니다.
   > 오늘 퇴근할 때 우유 사고, 이번 주 금요일까지 세탁소에서 옷 찾아야 해.
3. 두 개의 분석 결과를 확인합니다. 첫 할 일의 마감은 오늘, 두 번째는 이번 달력 주 금요일입니다. 이름·카테고리·마감·장소·중요도·메모를 수정한 후 저장합니다. 규칙에 맞지 않으면 **분석 없이 직접 입력**을 사용하세요.
4. **이동 추천**에서 회사 → 집, 집 → 회사, 집 → 동네 생활권 중 하나를 선택합니다. 장소와 추가 시간은 실제 검색 결과가 아닌 고정 샘플입니다.
5. **출발 전** 추천 카드에서 하나는 **경유지 추가**, 다른 하나는 **나중에 하기**를 누릅니다. 승인한 일은 진행 중으로 바뀌고 데모 경유지가 표시됩니다. 사용자 등록 장소는 바뀌지 않습니다.
6. **주행 시작 (데모)**을 누릅니다. 주행 집중 화면으로 바뀌며 등록·수정·완료 조작은 잠깁니다. 이 버튼은 실제 차량을 제어하지 않습니다.
7. 가상 도착을 시험할 때 **목적지 도착**을 누릅니다. 앱 내 도착 안내가 나타납니다. **도착만으로 할 일은 완료되지 않습니다.** 실제 위치 도착 감지는 하지 않습니다.
8. 처리한 할 일을 홈/이동 추천 목록의 체크 버튼으로 직접 완료합니다. **기록 → 완료**에서 완료 날짜와 내용을 확인합니다.
9. **주차 완료**를 누릅니다. 처리하지 않은 추천·진행 중 업무는 미완료로 남습니다.
10. **다음 이동 준비 (데모)**를 누릅니다. 새 이동 ID로 출발 전 화면이 열리며 앞서 미뤘거나 처리하지 못한 일을 다시 추천합니다. **먼저 추천을 확인한 다음 주행 시작**을 누르세요.
11. 앱을 완전히 종료한 후 다시 실행합니다. 업무·완료 시각·데모 경유지·미루기·이동 상태가 유지되는지 확인합니다.

## 3. 화면

- **홈**: 오늘 남은 일 / 오늘 완료 / 마감 임박 / 경로 내 추천, 차량 상태, 첫 추천, 오늘 할 일, 추가 버튼.
- **할 일 등록**: 외부 기기 음성 인식기 또는 텍스트, 규칙 기반 분석, 결과 수정, 수동 등록, 일괄 저장.
- **이동 추천**: 가상 현재 위치·목적지, 데모 상태 전환, 승인한 데모 경유지, 추천 이유·고정 추가 시간, 승인·미루기.
- **기록**: 전체/완료/미완료, 카테고리, 등록일/마감일/완료일 기준 날짜 필터, 수정·삭제·완료 취소.

### 숫자와 상태의 기준

- 오늘 남은 일: 완료되지 않았으며 마감이 없거나 오늘까지인 업무. 지난 마감도 포함합니다.
- 오늘 완료: 기기 시간대 기준 오늘 사용자가 완료한 업무.
- 마감 임박: 미완료 업무 중 내일까지 마감인 항목. 이미 지난 마감도 포함합니다.
- 경로 내 추천: 선택한 데모 경로에서 현재 추천 가능한 항목 수. 실제 주행 가능 여부가 아닙니다.
- 상태: 예정 → 실행 추천 → 진행 중 → 사용자가 체크하면 완료. 주차 때 남은 추천·진행 중 업무는 미완료가 됩니다.
- 기록의 **미완료 필터**는 완료 이외의 모든 상태를 보여 줍니다. 개별 **미완료 상태**와는 범위가 다릅니다.
- 추천 우선순위: 마감이 빠른 순 → 같은 마감이면 중요도 높은 순 → 샘플 추가 시간이 짧은 순.
- 마감 7일 이내 또는 날짜 없는 업무에서 카테고리가 일치하는 샘플 장소만 추천합니다. 기타 카테고리는 장소를 임의 생성하지 않습니다.
- 추천이 있는 연체 업무는 실행 추천으로 표시될 수 있지만, 마감 날짜와 미완료 이력은 유지됩니다.
- 나중에 하기는 현재 이동 ID 동안만 숨깁니다. START는 이동 ID를 바꾸지 않고, 주차 후 **다음 이동 준비**에서만 새 ID가 할당됩니다.
- 경로 변경은 출발 전/주차 후에만 허용합니다. 진행 중인 데모 경유지는 새 경로에서 재검토하도록 예정으로 돌립니다.

## 6. 데이터·권한·한계

- 모든 업무는 기기 내부 Room SQLite DB에 저장합니다. 계정·서버 동기화·분석 SDK·광고는 없습니다. Android 자동 백업은 꺼 두었습니다. 앱 삭제/데이터 지우기는 모든 기록을 삭제합니다.
- 샘플은 첫 DB 초기화 시 한 번만 생성됩니다. 모두 삭제한 뒤 재실행해도 다시 생성하지 않습니다. 샘플을 복구하려면 기기 설정에서 앱 데이터를 지우거나 재설치하세요.
- 이 앱은 직접 마이크를 녹음하지 않고 Android 외부 음성 인식 화면을 호출합니다. 앱 자체에는 RECORD_AUDIO 권한을 요청하지 않습니다. 기기 인식기에서 권한을 거부하거나 앱이 없으면 텍스트로 대체합니다. 오프라인 선호 옵션은 보장 조건이 아닙니다. 인식기의 별도 네트워크/개인정보 정책을 확인하세요.
- 현재 알림은 **앱을 열어 둔 상태의 안내 카드와 스낵바**입니다. 백그라운드 위치 감지, 시스템 푸시/상태바 알림, 실제 차량 이벤트, 자동 음성 안내는 구현하지 않았습니다. 앱이 닫혀 있을 때 자동으로 알리지 않습니다.
- 규칙 분석은 범용 AI가 아닙니다. 오늘/내일/모레, YYYY-MM-DD, 이번 주/다음 주 요일과 일부 접속 표현을 처리합니다. 절 안의 첫 날짜를 쓰며 다음 절에 날짜를 이어 적용합니다. 잘못된 날짜는 마감 없음으로 남으므로 저장 전 확인하세요.
- 주는 월요일 시작입니다. 주말에 입력한 '이번 주 금요일'은 이미 지난 날짜일 수 있습니다. 시간·휴일·복잡한 반복 일정은 지원하지 않습니다.
- 실시간 지도, 영업시간 확인, 실제 경유지 내비게이션 전송, 최적 경로 계산, 지오펜싱은 없습니다. 장소·이동 시간은 가상 값입니다. 사용자가 지정한 실제 장소와 다른 데모 장소를 제안할 때는 그 사실을 카드에 표시합니다.
- Pleos Connect용 프로젝트나 SDK 연동/공모전 심사 요건 검증이 완료된 결과물이 아닙니다. [확장 설계](docs/ARCHITECTURE.md)를 바탕으로 별도 차량 환경 검증이 필요합니다.

## 7. 문제 해결

- Java 오류: Gradle JDK를 17로 설정하고 터미널 JAVA_HOME도 같은 JDK로 맞춥니다.
- SDK 오류: Android Studio SDK Manager에서 API 35 설치, local.properties의 sdk.dir 자동 설정 여부를 확인합니다. 개인 SDK 경로를 다른 사람에게 그대로 복사하지 마세요.
- 의존성 다운로드 오류: 첫 빌드는 인터넷이 필요합니다. Gradle 오프라인 모드 해제, Google Maven/Maven Central 접근 여부를 확인합니다. Gradle Sync 오류 전체 로그를 기준으로 진단하세요.
- 주행 중 등록 화면을 못 여는 경우: 의도한 잠금입니다. 데모 **목적지 도착**을 누른 뒤 편집하세요.
- 주차 후 추천이 없는 경우: **다음 이동 준비 (데모)**를 눌러 출발 전 추천을 먼저 확인합니다.
- 추천이 없는 기타 카테고리 업무: 샘플 장소가 없기 때문입니다. 업무는 목록에 유지되며 수동 완료가 가능합니다.
